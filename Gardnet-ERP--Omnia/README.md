# Gestion des rôles

Version : 3.0

---

# Philosophie

Gardnet ERP utilise volontairement un système de permissions très simple.

Le but est :

- simplicité
- rapidité
- facilité de maintenance

Nous refusons un système complexe avec des dizaines de rôles.

---

# Rôles officiels

Le système possède uniquement deux rôles principaux.

1. Administrator
2. Contrôleur

Aucun autre rôle n'existe dans la version actuelle.

---

# Administrator

L'Administrator possède un accès complet.

Il peut :

- créer des utilisateurs
- modifier des utilisateurs
- supprimer des utilisateurs
- modifier tous les paramètres
- accéder à toutes les applications
- consulter toutes les données
- effectuer toutes les opérations

Il est le responsable de toute la plateforme.

---

# Contrôleur

Le Contrôleur est l'utilisateur métier.

Il travaille quotidiennement avec les applications.

Le Contrôleur est divisé en trois profils.

---

## Contrôleur Gardiennage

Accès uniquement aux données Gardiennage.

Applications autorisées :

- Pointage
- Stock-Doc
- Frais de Caisse
- Walkie Talkie
- Patrol
- Congé

Toutes les opérations concernent uniquement le Gardiennage.

---

## Contrôleur Nettoyage

Même fonctionnement.

Toutes les opérations concernent uniquement le Nettoyage.

---

## Contrôleur Mixte

Le Contrôleur Mixte peut gérer :

- Gardiennage
- Nettoyage

Il utilise exactement les mêmes applications.

---

# Gestion des droits

Le système reste flexible.

L'Administrator peut :

- activer une application
- désactiver une application

pour un utilisateur particulier.

Exemple :

Contrôleur A

✔ Pointage

✔ Patrol

✔ Congé

❌ Walkie Talkie

❌ Frais de Caisse

---

# Principe de simplicité

Les permissions ne doivent jamais devenir compliquées.

Le projet privilégie :

- quelques rôles
- quelques permissions

plutôt qu'un système difficile à comprendre.

---

# Walkie Talkie

Version : 3.0

---

# Objectif

Walkie Talkie est l'application qui permet de gérer le parc des radios du Groupe Gardnet.

Son rôle est de connaître à tout moment :

- où se trouve chaque appareil,
- à quel site il est affecté,
- qui l'utilise,
- dans quel état il se trouve.

---

# Philosophie

L'application doit être extrêmement simple.

Elle ne gère pas les communications radio.

Elle gère uniquement les équipements.

---

# Gestion des appareils

Chaque appareil possède une fiche.

Informations minimales :

- Numéro de série
- Marque
- Modèle
- Date d'ajout
- Statut
- Site d'affectation
- Observations

---

# Numéro de série

Le numéro de série est unique.

Le système interdit automatiquement :

- l'ajout d'un appareil déjà enregistré.

Si le numéro existe déjà :

Le logiciel affiche immédiatement :

> Cet appareil est déjà enregistré.

Aucun doublon n'est autorisé.

---

# Statut

Chaque appareil possède un état.

Exemples :

- En service
- En réserve
- En réparation
- Hors service
- Perdu

L'Administrator peut ajouter d'autres états si nécessaire.

---

# Affectation

Chaque appareil peut être affecté :

- à un site,
- ou rester disponible au dépôt.

---

# Historique

Chaque changement est enregistré.

Exemple :

01/03/2027

Affecté au Site A

↓

15/04/2027

Transféré au Site B

↓

10/05/2027

Retour au dépôt

Le logiciel conserve tout l'historique.

---

# Ajout d'un appareil

Le contrôleur saisit :

- Numéro de série
- Marque
- Modèle
- Site
- État

Validation.

L'appareil devient immédiatement disponible.

---

# Modification

Les informations peuvent être modifiées.

Toutes les modifications restent enregistrées.

---

# Suppression

Un appareil n'est jamais réellement supprimé.

Il devient :

Inactif

Son historique reste conservé.

---

# Recherche

Recherche rapide par :

- Numéro de série
- Site
- État
- Marque
- Modèle

---

# Situation mensuelle

À la fin de chaque mois,

le contrôleur établit la situation mensuelle.

Exemple :

Nombre d'appareils :

- En service
- En réparation
- Hors service
- Disponibles

Cette situation peut être :

- imprimée,
- exportée en PDF,
- exportée en Excel.

Le partage reste manuel.

---

# Nouveaux appareils

Le logiciel permet :

- d'ajouter un nouvel appareil,
- sans limite.

---

# Remplacement

Un appareil peut remplacer un autre.

L'ancien appareil conserve toujours son historique.

- Ajouter
- Modifier
- Rechercher
- Exporter

L'enregistrement signifie que le congé est accepté.

---

# Philosophie

Le logiciel ne décide jamais.

Le contrôleur décide.

Le logiciel archive.

---

# Structure

Entreprise

↓

Activité

↓

Employé

↓

↓

Historique

- Employé

- Date de fin
- Type de congé
- Observation (optionnelle)

Le congé devient immédiatement officiel.

---

# Aucune validation

Le logiciel ne possède pas :

- Validation
- Refus

Le contrôleur saisit directement le congé.

Tous les congés restent archivés.

Jamais supprimés.

# Development Constitution v4.0

## Project Philosophy

Gardnet ERP is built on one fundamental principle:

**Simplicity before everything.**

Every development decision must follow this priority:

1. Simplicity
2. Stability
3. Speed
4. Beauty

The objective is not to create the most complex ERP.

The objective is to create the most efficient ERP.

---

## Official Development Workflow

The official workflow of the project is:

GitHub
↓

VS Code

↓

Lovable (Free)

↓

Bolt (Free if necessary)

↓

VS Code

↓

GitHub

GitHub is always the official source of the project.

Lovable and Bolt are development assistants only.

---

## Free Platforms Policy

The project is intentionally designed around free platforms.

Every technical decision must respect:

- free plans;
- daily quotas;
- token limitations;
- lightweight architecture.

Paid services are avoided whenever possible.

---

## Artificial Intelligence Constitution

Artificial Intelligence must:

- respect the official Constitution;
- never modify validated decisions;
- never complicate the architecture;
- always generate clean and maintainable code;
- always preserve the French language.

The entire platform is developed in French.

This includes:

- interface;
- menus;
- buttons;
- forms;
- messages;
- generated application content.

Automatic translation into another language is not allowed.

## User Interface Philosophy

The interface must always be:

- modern;
- clean;
- lightweight;
- responsive;
- intuitive.

Beauty is important.

Performance is more important.

Animations are welcome only if they remain lightweight.

Dark mode is accepted only if it does not significantly increase development time.

## Official Motto

Beautiful through simplicity.

Fast through simplicity.

Professional through simplicity.

Build first.

Improve continuously.

## Constitution Rule
